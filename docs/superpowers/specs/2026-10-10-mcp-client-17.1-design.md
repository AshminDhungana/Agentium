# Design: MCP Client Fix & Verify — TODO 17.1 (17.1.1–17.1.4)

**Date:** 2026-10-10
**Scope:** Verify and fix TODO.md §17.1 — MCP Client items. This is a verify-and-fix task, not a build: the full MCP stack (`mcp_client.py`, `mcp_tool_bridge.py`, `mcp_governance.py`, routes, model, migration, tests) already exists and is wired at startup (`backend/main.py:473-474`).

## Findings (what's broken today)

1. **`connect()` is broken in real mode** (`backend/services/mcp_client.py:65-82`) — two defects:
   - `stdio_client(params).__aenter__()` yields `(read_stream, write_stream)`, but the code unpacks it as `(transport, session)` and calls `initialize()` on a raw memory stream → `AttributeError` on every real connection. The SDK requires wrapping the streams in `ClientSession(read, write)` first.
   - `server_url` is passed as a stdio **command name**. HTTP URLs (`http://…`) can never connect, and multi-word commands fail because the whole string becomes the executable name.
   - The mock fallback (`MCP_AVAILABLE = False`) answers every call, which masked both defects in CI. `mcp==1.28.1` is pinned in requirements, so the broken real path is what production hits.
2. **`call_tool` ignores the protocol's `isError` flag** (`mcp_client.py:136-144`) — a tool that responds with an error is reported as `"success": True`.
3. **Capability discovery corrupts schemas** (`backend/services/mcp_governance.py:158-166`) — `list_tools()` returns dicts keyed `name`/`description`/`input_schema`, but the loop reads them with `getattr(t, "description", "")` / `getattr(t, "inputSchema", {})`. `getattr` on a dict never raises, so every stored capability gets an empty description and empty input schema. Downstream, the tool bridge (17.1.4) can build no Pydantic validation models, and agents see schema-less tools.
4. **Zero test coverage for `MCPClient`** — no `test_mcp_client.py` exists anywhere in the suite.

The tool bridge itself (17.1.4) is healthy: startup sync, tier gating, immediate deregistration, and revocation tests all exist. The fix work is in the client and one governance loop.

## Approved approach (from brainstorm)

**Approach A — surgical fix, keep all public interfaces unchanged.** Alternatives considered and rejected: a transport-abstraction rewrite (over-engineered for a deliberately thin wrapper) and client-only fix without tests (would check boxes without evidence; user chose live-server verification).

## Design

### 1. Transport auto-detect in `MCPClient.connect()` — fixes 17.1.1

- A module-level helper classifies `server_url`: `http://` or `https://` scheme → HTTP transport; anything else → stdio command.
- **HTTP path:** `streamablehttp_client(url)` (verified against installed `mcp==1.28.1`: signature `(url, headers=None, timeout=30, sse_read_timeout=300, …)`, yields `(read, write, get_session_id)`). Only the first two streams are used.
- **stdio path:** `shlex.split(server_url)` → `StdioServerParameters(command=parts[0], args=parts[1:])`. On Windows, if the command resolves to an obvious script path, run it via `sys.executable` (fixture support; guarded, not a shell).
- **Session layer (the core fix):** both paths store the transport context manager plus `(read, write)`, then create `ClientSession(read, write)` and `await session.initialize()`.
- **Teardown:** `disconnect()` exits in reverse order — session `__aexit__` first, then transport `__aexit__` — both best-effort (existing behavior).
- Public API signatures (`connect`, `disconnect`, `list_tools`, `call_tool`, `health_check`) are unchanged, so the four call sites in `mcp_governance.py` (lines 149, 489, 530, 581) need no interface changes.
- Timeout and `MCPConnectionError` wrapping in `connect()` is preserved.

### 2. `call_tool` result fidelity — completes 17.1.3

- Pass `arguments=params` explicitly to `session.call_tool()`.
- Read the protocol's `isError` flag: return `"success": not response.isError` while keeping the result/error dict contract governance depends on (errors are returned as dicts, never raised, except connection failures at `connect()` time).

### 3. Governance capability-dict fix — completes the 17.1.4 chain

- `mcp_governance.py:158-166`: replace `getattr(t, "description", "")` → `t.get("description", "")` and `getattr(t, "inputSchema", {})` → `t.get("input_schema", {})`, matching what `list_tools()` actually returns. This is what lets the bridge build per-sub-tool Pydantic validation models and surface parameter descriptions to agents.

### 4. Testing — live-server verification (user-approved)

- **New fixture:** `backend/tests/fixtures/fake_mcp_server.py` — a minimal `FastMCP` server (bundled in the `mcp` package) exposing:
  - `echo(text: str) -> str`
  - `add(a: int, b: int) -> int` (typed schema, exercises required-integer properties)
  - `fail() -> str` — a tool that returns an error result (exercises the `isError` path)
  - Runs over stdio by default (`python fake_mcp_server.py`) and can host streamable-http on an ephemeral port via a flag.
- **Live stdio test** (`backend/tests/integration/test_mcp_client.py`): spawn the fixture via `sys.executable` as a real subprocess; assert real handshake (`connect()` + `initialize()` succeeds), real `list_tools()` returns the three tools with non-empty `input_schema`, real `call_tool("add", {"a": 2, "b": 3})` returns `5`, `fail()` reports `success: False`, and `health_check()` reports healthy with latency and `tool_count == 3`.
- **Live HTTP test:** run the same fixture with `streamable-http` transport on an ephemeral localhost port (background asyncio task); assert auto-detect routes an `http://127.0.0.1:<port>/mcp` URL through the HTTP path and discovery/invocation work. Marked to skip gracefully if the port can't bind.
- **Unit tests** (`backend/tests/unit/test_mcp_client_unit.py`):
  - transport classification (URL vs command string)
  - bogus stdio command → clean `MCPConnectionError`, not a raw crash
  - mock-fallback mode with `MCP_AVAILABLE` monkeypatched to `False` (degraded-environment path keeps working)
- **Governance regression test:** propose a server backed by the fixture and assert stored capabilities carry non-empty `input_schema` and `description` — the assertion whose absence let bug #3 ship.

### 5. Error handling

- `connect()` failures raise `MCPConnectionError` (existing contract; governance already catches this at proposal time).
- `call_tool()` failures and timeouts return error dicts (unchanged contract).
- No behavioral changes to governance flows (voting, approval, revocation) — those are 17.2 territory and already tested.

### 6. Out of scope

- `datetime.utcnow()` deprecation (pre-existing, repo-wide).
- §17.2 governance items and §17.3 API items.
- Connection pooling / session reuse / background health polling (YAGNI for a thin wrapper).

## Acceptance criteria

- All four 17.1.x boxes in `docs/documents/TODO.md` checked only after:
  - live stdio test proves handshake, discovery, invocation (17.1.1–17.1.3);
  - live HTTP test proves URL auto-detect (17.1.1);
  - governance regression test proves capabilities retain schemas end-to-end into the bridge (17.1.2, 17.1.4);
  - full existing MCP test suite (bridge schema, agent tools, revocation, registration) stays green.
